# Personal flight deals

This fork adds `/deals`, a structured flight monitoring form. Indonesia is the initial origin country, with CGK and DPS selected. Select any country and its airports on either side; country selection is expanded into explicit airport routes. The catalog includes airports without scheduled commercial service, so choose the airports you can use. Destination countries must be selected explicitly; worldwide discovery is not implemented.

Outbound and return windows are independent and inclusive. Every valid pair is checked, excluding returns on or before departure. One-way windows cover every day. Each window is limited to 31 days, each route to 64 date pairs, each creation to 20 routes and 256 checks per cycle. The form displays the actual workload and the API enforces these limits without silent sampling. Sources can still block or fail individual checks; these appear as partial/failed runs. The scanner is sequential, so broad windows can take a long time and incur provider costs.

`maxStops` limits the displayed outbound itinerary. `maxDurationHours` includes outbound connections. `maxLayoverHours` limits each outbound connection separately. In deal mode, unknown journey duration cannot satisfy an enabled journey cap; missing or incomplete connection evidence cannot satisfy a layover cap. The existing scrapers often expose only outbound itinerary details even when quoting a round-trip ticket. **Return itinerary duration, return stops, baggage and checkout total are not verified by these filters.** Check them at the seller before purchasing.

## Usual prices and notifications

The initial alert threshold is 30%, adjustable at creation and in the tracker. It compares the current eligible fare against the median of daily minimum eligible prices from the previous 30 UTC days. Five distinct prior observation days are required. Each day contributes once, regardless of polling frequency. Comparisons remain within one airport route and cabin, exact outbound/return dates, currency, number of stops, and VPN market. History before a recorded criteria edit is excluded. This is your observed normal price, not a provider-supplied market average; warmup cannot identify deals immediately. A persistent drop eventually enters the rolling baseline.

Deal trackers use their discount policy instead of the legacy new-low/custom-price rules. The strongest qualifying deal per route and cycle enters the existing durable notification outbox. Identical prices for the same dates, criteria and market are deduplicated. Different dates can produce separate events. There is no additional deal cooldown, so a changing deal can notify on each configured scrape cycle. Notification channels and pause/scrape intervals use existing tracker controls. Set up Telegram, email, ntfy or another supported channel in Settings and select it in the tracker's Notifications panel. Creating a tracker does not configure or test delivery.

## Local setup

Use Node 22+ and the repository's npm workspaces. Supply `DATABASE_URL` for your PostgreSQL database and optionally `REDIS_URL`. Do not commit environment files or credentials. Install dependencies, generate Prisma, apply the additive schema using the documented upstream database setup, and initialize private access using `npm run cli -- access initialize` followed by `npm run cli -- access setup`. Existing snapshots keep null return dates and legacy query semantics. The new fields are nullable/defaulted; old trackers retain their previous behavior.

For an HTTPS development preview, `apps/web/package.json` sets Portless name `flight-finder`, and the dev script honors `PORT`. Run `portless` from `apps/web` with `SELF_HOSTED=true` and `APP_URL` matching the displayed HTTPS origin. If privileged ports are unavailable, use `PORTLESS_PORT=1355` and `APP_URL=https://flight-finder.localhost:1355`. Configure extraction credentials/model in Settings through the existing provider setup. No Trip.com, OneTwoTrip or AirAsia direct API is added; source coverage remains that of upstream Flight Finder, and booking follows the observed seller link.

GitHub Actions is disabled for this personal fork. Run `npm run ci` locally: web/CLI lint, typecheck, tests and both builds. Focused tests cover date grids, return identity, comparable-price baselines, cold start and strict time limits. `scripts/deals/browser-test.mjs` verifies the structured form, server rejection of oversized windows, and tracker status against an initialized disposable local PostgreSQL instance with browser session fixture. With a disposable initialized database and no enabled channels, run `TSX_TSCONFIG_PATH=apps/web/tsconfig.json node --import tsx scripts/deals/alert-test.mts` to verify real PostgreSQL warmup, outbox deduplication and delivery authority without sending notifications.
